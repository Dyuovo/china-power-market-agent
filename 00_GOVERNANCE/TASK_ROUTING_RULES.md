## 分流流程

1. 识别任务关键词和最终输出。
2. 判断任务是治理、业务、学习、数据还是跨域。
3. 检查是否已有对应 Skill。
4. 如果已有 Skill，按 Skill 执行或调用。
5. 如果没有 Skill，但会重复使用，建立 Skill 草稿。
6. 如果跨域，由小枢拆解后分配给对应执行层 Agent。
7. 如果已明确目标 Agent，可以直接发送给对应 Agent，但仍要遵守边界。
8. 如果任务跨日、跨 Agent、来自 cron、可能阻塞或不能当轮闭环，先写入任务账本。

任务账本命令：

```bash
python3 <workspace>/08_TOOLS/task_ledger.py add --title "任务标题" --owner xiaoshu --source user
```

## 小枢处理边界

小枢可以：

- 判断任务归属。
- 拆解跨 Agent 任务。
- 设计执行模板。
- 建立文件、规则和 Skill。
- 维护注册表和版本日志。

小枢不应该：

- 直接替小霆生成业务日报。
- 直接替小霆做客户报价决策。
- 直接替小电讲完整课程。
- 直接替小电完成长期学习辅导。

## 冲突处理

如果任务归属不明确，按以下优先级判断：

1. 如果目标是“产出业务结果”，优先小霆。
2. 如果目标是“理解知识或建立学习能力”，优先小电。
4. 如果目标是“让系统以后更稳定地完成这类事”，优先小枢。
5. 如果多者都有，由小枢拆解。

## 输出要求

分流结果应至少包含：

- 归属 Agent
- 判断理由
- 是否需要 Skill
- 是否已有 Action
- 是否需要任务账本
- 需要的输入
- 预期输出
- 是否需要 A2A 转发

## A2A 转发规则

跨 Agent 执行任务必须使用 `AGENT_MSG_SPEC.md` 的标准类型：

- `TASK_ASSIGN`
- `TASK_ACK`
- `TASK_DONE`
- `TASK_BLOCKED`

小枢发出 `TASK_ASSIGN` 前，必须先创建或引用 `TASK-YYYYMMDD-NNN`。
