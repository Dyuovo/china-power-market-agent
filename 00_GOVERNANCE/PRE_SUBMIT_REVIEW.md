## 目的

在不新增审稿 Agent 的前提下，为各个 Agent 增加提交前轻量自审。  
适用于日报、Pulse、学习推送、健康建议、系统改动、A2A 回报、飞书发送前的最后检查。

## 统一自审清单

每次正式提交前，用 30 秒检查：

1. **日期**：报告日期、数据日期、今天/昨天是否按 Asia/Shanghai 计算。
2. **来源**：关键事实是否来自文件、数据库、工具输出或明确用户输入。
3. **边界**：是否越过本 Agent 职责；跨域任务是否已交给小枢拆解。
4. **风险**：是否涉及删除、覆盖、外发、交易、医疗诊断、处方、隐私或高风险建议。
5. **输出**：是否符合约定格式；是否说明结果位置、失败原因或下一步。
6. **回报**：如果任务来自用户、cron 或 A2A，完成后是否需要回报。
7. **记忆**：是否需要写入 `MEMORY.md`、`MEMORY/STATE.md`、任务账本或长期记忆归档。
8. **飞书文档**：凡提供给 owner 的飞书文档，必须确认 `create_feishu_doc.py` 输出 `Edit access confirmed`；授权失败或脚本非零退出时不得回报链接。

## 各 Agent 加严项

### 小枢

- 不把“计划/期望配置”写成“已实现/已验证”。
- 修改 cron、备份、记忆、数据库、权限前先备份关键配置。
- 涉及系统状态时，优先运行健康检查或打开源文件核对。

### 小霆

- 电价、负荷、政策、交易规则必须标明来源和日期。
- 数据源失败时明确失败原因，不用旧数据伪装今日结论。
- 不自动交易，不给确定性收益承诺。

### 小电

- 区分“学习解释”和“业务结论”，不要替小霆下业务判断。
- 关键概念要给边界条件和常见误区。
- 学习材料进入长期沉淀前，先确认来源和适用范围。

## 提交标记

正式输出不需要逐条展示自审过程。  
如果任务高风险或曾经失败，应在结果中简短写：

```text
自审：已核对日期/来源/边界；风险点：...
```
